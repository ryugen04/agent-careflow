## Situation

The original requirement explicitly allows or expects intermediate products under `.agent`/`.agents`-style locations. The current implementation has canonical `.careflow` artifacts and a `.careflow/INDEX.md` dashboard, but no `.agent` operator workspace.

## Background

Tool-specific `.agents` is already reserved for Codex skill discovery and must not be written into target repositories as runtime state. A singular `.agent` directory can safely serve as a human-facing workspace that points to canonical `.careflow` artifacts without becoming the source of truth.

## Assessment

A generated `.agent` workspace will improve cross-session usability: humans and agents can open `.agent/current.md` first, then follow fixed links to the active PLAN/ORDER/RESULT, incidents, and learnings. This keeps the canonical state deterministic in `.careflow` while satisfying the user's requested artifact ergonomics.

## Recommendation

Implement `agent-careflow workspace --write`, generate `.agent` markdown entrypoints from current state, add tests/docs, run focused verification, and update the expected result artifact.
