## Situation

Codex CLI 0.139.0 `codex exec` has runtime-observed evidence that `UserPromptSubmit` capture hooks do not fire in the probed surface, while the prompt itself reaches the model. The objective cannot honestly call this fixed through native hooks.

## Background

The same prompt policy already blocks synthetic secrets and PHI-like identifiers in direct hook/conformance tests. The missing piece is an enforced Codex entrypoint for non-interactive runs when native `UserPromptSubmit` is not observable.

## Assessment

A wrapper does not prove native hook behavior. It does provide a controllable entrypoint that runs the same pre-model prompt guard before invoking Codex, which is meaningful progress toward the user goal when installed or used as the standard Codex launcher.

## Recommendation

Implement `agent-careflow codex exec` as a guarded Codex launcher. Keep native hook residuals visible in audit, but add separate wrapper mitigation evidence so future dotfiles integration can choose the wrapper as the default entrypoint.
