## Situation

The system can resolve `.careflow` from nested worktrees, but the operator workspace does not yet clearly list the multi-repo root layout or `.worktrees/<branch>/<repo>` entrypoints the user described.

## Background

Business apps may live under a parent `root-xxxx` folder with centralized `.codex`, `.claude`, `.agents`, and `.careflow` configuration. Actual repositories may be direct children such as `backend` and `frontend`, or branch worktrees under `.worktrees/{branch}/{repo}`.

## Assessment

Agents should not have to infer this layout from chat history. The root workspace should expose repo/worktree status and command roots as durable artifacts.

## Recommendation

Add repo/worktree status detection and include it in `.agent/` so Claude, Codex, and subagents can orient themselves from the root without scattering artifacts into each repository.
