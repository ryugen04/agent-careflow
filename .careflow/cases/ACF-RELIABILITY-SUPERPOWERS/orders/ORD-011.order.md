## Situation

The native Codex `UserPromptSubmit` hook remains runtime-observed failing for the probed `codex exec` surface. ORD-009 and ORD-010 added a guarded wrapper and dotfiles launcher distribution, but the incident remains open because there is no formal policy for accepting that wrapper as the enforced non-interactive Codex boundary.

## Background

The user rejected small prose-rule changes as insufficient. A residual can only be considered handled if a machine-readable artifact proves the stronger behavior: wrapper preflight exists, the launcher is distributed, rejected prompts are blocked before Codex invocation, and operators can audit this state later.

## Assessment

The truthful state is not "native hook fixed". The truthful state can become "native hook limitation remains, but non-interactive Codex execution is covered by an accepted guarded-entrypoint policy" if the acceptance artifact and audit checks make that explicit.

## Recommendation

Implement a mitigation acceptance record and objective-audit checks that allow INC-001 to close only under that explicit policy. Preserve the native hook failure check as separate evidence so future Codex runtime fixes can replace the mitigation instead of burying the limitation.
