## Situation

ORD-009 created `agent-careflow codex exec`, but it is not yet distributed into the user's dotfiles install path. Without distribution, the mitigation is too easy to forget.

## Background

The user specifically needs unified Codex/Claude settings across business/private machines and wants more than prose rules. The dotfiles installer already installs Codex hooks, config, and careflow skills from the agent-careflow repo.

## Assessment

The guarded launcher should be installed as an explicit command such as `codex-careflow`, not by silently replacing `codex`. This makes the safer entrypoint easy to use while preserving transparency.

## Recommendation

Update dotfiles installer to create/remove a managed `~/.local/bin/codex-careflow` launcher that delegates to `agent-careflow codex exec`, document it, verify it against a fixture home, and record evidence.
